# Диспетчерский dashboard «Такт»

Эта ветка содержит только web-интерфейс: HTML, CSS, JavaScript, карту Leaflet,
административную страницу и встроенное руководство по API. Backend, ML,
датасеты и эмуляторы находятся в других ветках.

## Рабочее место диспетчера

Главная страница `dashboard/dispatcher.html` показывает только операционно
необходимые данные:

- очередь рейсов, требующих проверки;
- карту ТС и плановую траекторию;
- фильтр и таблицу всех доступных ТС;
- текущую позицию, прогноз T+10…T+15, целевую остановку и источник данных;
- предыдущую и следующую остановку с расчётными временами прохождения;
- карточку выбранного ТС с деталями телеметрии;
- режим следования за выбранным транспортом на карте;
- what-if выпуск резервного ТС с отображением результата на карте.

В карточке явно разделены:

- **сейчас** — `current_deviation_s`, оценка положения на текущем сегменте;
- **прогноз** — `prediction_s`, ожидаемое отклонение на будущей контрольной точке;
- источник — live NDTP, custom NDTP, архив или `waiting_for_live`.

Интерфейс не «исправляет» результат модели: backend передаёт V5-прогноз и
калиброванный интервал без эвристического сдвига. При отсутствии остановки в
строгом окне 10–15 минут показывается «Нет контрольной точки», а не нулевое
отклонение или чужая остановка.

Отдельно показан операционный статус рейса: выход не подтверждён, активен,
завершён, поток приостановлен или связь потеряна. Критическая потеря связи
поднимается выше обычного модельного риска; последняя позиция остаётся на
карте, а устаревший прогноз скрывается.

## Администрирование

`dashboard/admin-control.html` содержит три рабочих блока:

1. состояние общего контура и количество ТС;
2. пауза, остановка и возобновление custom/original NDTP-потоков;
3. создание и удаление кабинетов диспетчеров и назначение рейсов галочками.

Администратор выбирается через локальный профиль и открывает эту страницу;
пароли и SSO в прототипе не имитируются. Управление потоками доступно любому
вошедшему рабочему профилю, если backend это разрешает.

Встроенный старший профиль называется «Диспетчер №2 (все ТС)» и по умолчанию
видит весь парк. Диалог выбора профиля можно безопасно закрыть крестиком,
Escape, кнопкой «Отмена» или кликом по фону; незавершённый выбор не применяется.

## Справочные страницы

- `dashboard/docs.html` — объяснение полей, источников, прогнозов, what-if и
  ограничений прототипа;
- `/docs/swagger` — живой Swagger backend;
- `/code/` — Sphinx-документация кода backend/ML в полном запуске.

Навигация в шапке диспетчерской оставляет только три полезные ссылки:
описание API, документацию кода и исходный код проекта.

## Как frontend получает данные

Интерфейс не содержит собственную модель и не хранит расписание. Он опрашивает
backend и обновляет карту/таблицу по ответам:

| Endpoint | Использование |
|---|---|
| `GET /api/state` | ТС, прогнозы, источники и режим live/replay |
| `GET /api/network` | Плановые последовательности остановок |
| `GET /api/incidents`, `GET /api/risk` | Очередь внимания и сводка риска |
| `POST /api/what-if` | Сценарий выпуска резерва |
| `GET /api/dispatchers` | Выбор рабочего профиля |
| `GET /api/admin/emulators` | Статус двух потоков |
| `POST /api/admin/emulators/{id}/{action}` | pause/stop/resume |
| `/api/admin/dispatchers/*` | Кабинеты и назначения рейсов |

После выбора ТС список, карта и боковая карточка используют один `tr_id`.
Карта приближает масштаб и может следовать за маркером, пока выбран режим
«Следить за ТС».

## Файлы ветки

- `dispatcher.html`, `dispatcher.css`, `dispatcher.js` — основное рабочее место;
- `admin-control.html`, `admin.css`, `admin.js` — административный контур;
- `docs.html`, `docs.css`, `docs.js` — пользовательская документация;
- `map.js`, `map-config.js` — Leaflet-карта, маршруты, маркеры и резерв;
- `nginx.conf` — проксирование интерфейса к `backend:8000`;
- `vendor/leaflet/` — локальные ресурсы Leaflet без CDN-зависимости.

## Запуск в полном прототипе

Эта ветка не содержит Compose и backend, поэтому сама по себе является
статическим frontend-пакетом. В полном проекте Nginx использует конфигурацию
`nginx.conf` и проксирует запросы к backend на `backend:8000`; backend возвращает
страницы из этого каталога и API в одном origin.

Для локального предпросмотра HTML можно использовать любой статический сервер,
но без прокси API карта и таблица не получат данные. Интеграционный запуск и
переменные окружения описаны в README корневой ветки `prototype`.
