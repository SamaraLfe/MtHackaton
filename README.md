# ML-сервис «Такт»

Эта ветка содержит только модельный контур: построение причинных признаков,
обучение V5.2, единый набор артефактов CatBoost и самостоятельный HTTP-сервис инференса.
Backend, дашборд, эмуляторы и расписания находятся в других ветках проекта.

## Что делает ML-контур

ML-сервис получает исходную точку прогноза, историю телеметрии и плановые
остановки, после чего возвращает прогноз изменения отклонения от графика на
горизонте 10–15 минут. Положительное значение `prediction_s` означает
опоздание, отрицательное — опережение.

В рабочем артефакте используется CatBoost V5.2:

- 102 причинных признака;
- `tr_id` и `target_stop_id` исключены из признаков модели;
- история ограничена моментом `T`, будущие телеметрические строки не используются;
- общий causal feature builder отклоняет точки вне строгого окна
  `600 < target_time_begin - T <= 900`;
- модель обучается на residual `target_delay_s - cur_dev_s`, а runtime прибавляет
  известное на момент `T` текущее отклонение;
- ответ содержит split-conformal интервал и эмпирическую вероятность задержки.

Runtime возвращает уже восстановленное полное отклонение для будущей остановки:
`prediction_s = cur_dev_s + predicted_residual`. Поэтому текущая задержка не
теряется, а прогноз остаётся сопоставимым с backend-карточкой.

Диагностическая оценка сохранённого артефакта:

```text
test MAE:             73.64 с
persistence baseline: 93.36 с
improvement:          21.12%
interval coverage:    96.88%
```

Оценка получена на ограниченной исторической выборке. В ней один исторический
день, есть пересечение транспортов между выборками, нет разметки причин,
состояния дверей и официальных идентификаторов маршрутов.

## HTTP API

Запуск сервиса из корня полного проекта:

```sh
ARTIFACT_DIR=artifacts python -m uvicorn ml.service:app --host 0.0.0.0 --port 8001
```

Основные endpoints:

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | доступность процесса и имя загруженной модели |
| `POST` | `/predict_v5` | основной пакетный прогноз по исходным данным |
| `POST` | `/predict` | legacy-контракт 15 признаков; с V5 возвращает `410` |
| `GET` | `/docs` | Swagger ML API |
| `GET` | `/openapi.json` | OpenAPI-контракт ML-сервиса |

`/predict_v5` принимает три массива одинаковой длины. Для каждой точки нужен
строгий горизонт `600 < target_time_begin - T <= 900`; запрос вне окна получает
`422`.

Пример:

```json
{
  "points": [{
    "tr_id": 131672,
    "T": "2026-01-06T03:35:00Z",
    "target_stop_id": 53700172828,
    "target_time_begin": "2026-01-06T03:50:00Z",
    "cur_dev_s": 74
  }],
  "histories": [[{
    "event_time": "2026-01-06T03:34:50Z",
    "lon": 37.60,
    "lat": 55.75,
    "speed": 25,
    "location_valid": true
  }]],
  "schedules": [[{
    "tr_id": 131672,
    "tt_action_item_id": 53700172828,
    "time_begin": "2026-01-06T03:50:00Z",
    "geom": "POINT (37.60 55.75)"
  }]]
}
```

Каждый элемент ответа содержит `prediction_s`, `lower_s`, `upper_s`,
`late_probability`, `model` и `uncertainty`. Backend выбирает первую целевую
остановку в окне T+10…T+15 и проверяет её соответствие активному расписанию;
ML дополнительно валидирует сам числовой горизонт, но не выбирает остановку.

## Артефакты

Сервис загружает из `ARTIFACT_DIR`:

- `model.json` — метаданные и параметры калибровки;
- `model_v5.cbm` — CatBoost-модель;
- `v5_feature_schema.json` — порядок признаков;
- `metrics.json`, `feature_importance_v5.csv` — диагностика;
- `test_predictions_v5.csv`, `train_features.csv` — воспроизводимый аудит;
- `submission.csv` — единственный результат в формате задания.

Ветка уже содержит единственную копию сохранённых артефактов в каталоге
`artifacts/`; дублирующего `ml/artifacts/` нет.

## Обучение и проверка

Обучение V5 выполняется из корня проекта:

```sh
python -m ml.train --data dataset --out artifacts
```

Параметры `--data` и `--out` можно заменить на локальные каталоги с датасетом и
результатами. Для runtime-проверки используются тесты `ml/tests/test_v5_runtime.py`.

Сохранённый контракт можно экспортировать из полного проекта:

```sh
python scripts/export_openapi.py
```

Важно: этот README описывает только ML-ветку. Интеграционный запуск через
NDTP, backend и диспетчерскую находится в README соответствующих веток.
