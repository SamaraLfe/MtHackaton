# Проверка прогнозов эмуляторов · 26 сентября 2026

## Какие числа показывать

Основной показатель — `prediction_s`: ожидаемое отклонение на контрольной
остановке. Ожидаемое время прибытия = `target_time_begin + prediction_s`.
Плюс означает опоздание, минус — прибытие раньше расписания.
Горизонт выбора цели = `target_time_begin − T`, строго (600, 900] секунд.
Это горизонт **планового** прибытия; при задержке ожидаемое прибытие может
быть позднее T+15 минут.

`current_deviation_s` — оценка текущего положения относительно плана,
а не второй прогноз. Для сегмента с долей прохождения f:

```
expected_position_time = segment_start + f × segment_duration + live_offset
current_deviation_s = event_time − expected_position_time
```

Она полезна в диагностике и как вход модели. Дублировать её возле каждого
прогноза в таблице необязательно: основная карточка показывает прогноз,
расписание и ожидаемое время; текущая оценка доступна в раскрываемых деталях.

## Проверенные вычисления и исправления

1. Проекция на сегмент использует локальные метры, доля f ограничена [0, 1].
   Расстояние до сегмента нельзя использовать как расстояние до остановки.
   Исправлено: медленный пакет считается близким к остановке только по
   фактическому расстоянию до её координат (до 60 м). Даже такая близость
   остаётся оценкой, а не доказательством прибытия или открытия дверей.
2. Удалено обрезание текущего отклонения до ±1800 с: оно скрывало реальную
   величину расчётного расхождения с планом.
3. Удалены расширение горизонта на разреженном расписании и автоматическое
   добавление повторных рейсов при поиске цели. Если цели нет в (600, 900],
   позиция остаётся видимой, прогноз отсутствует.
4. Удалён `stabilize_forecast`: правило изменения не более половины горизонта
   (300–600 с) не учитывало расстояние, скорость и оставшийся путь, поэтому
   не являлось физическим ограничением. Оно ограничивало и рост задержки,
   а после сдвига прогноза архивная калибровка уже не была проверена.
   Backend теперь сохраняет результат и интервал ML без этого изменения.
5. Если текущая координата не сопоставилась с планом, старое отклонение
   больше не выдаётся за оценку новой позиции.
6. V5 использует историю не позднее T. Интервал задаётся замороженным
   эмпирическим радиусом по test-остаткам, риск задержки более 120 с — долей
   остатков выше `120 − prediction_s` со сглаживанием `(1 + count)/(n + 2)`.
   Это эмпирическая оценка; она не устанавливает причину задержки.

## Ограничения источников

Собственный эмулятор интерполирует позиции по времени плановых сегментов
с коэффициентом темпа. Live-offset привязывает первый пакет к условному
началу прогона: он не восстанавливает неизвестное опоздание до подключения.
На повторяющейся геометрии сопоставление может быть неоднозначным.

Для оригинального эмулятора backend заменяет случайные координаты
интерполяцией по плану. Это синтетическая позиция, а не наблюдение реального
движения. В карточке происхождение указано явно. Скорость генераторов
ограничивается/сглаживается отдельно от координат, поэтому на аномальных
плановых сегментах она может расходиться со скоростью между GPS-точками.

Модель и её калибровка обучены на исторических данных. Исправление вычислений
не доказывает качество прогнозов на синтетическом потоке: для этого нужны
истинные будущие прибытия эмулятора и отдельная оценка ошибок/покрытия.
Реальное расписание текущей даты, дорожный граф и подтверждение остановок
остаются внешними условиями промышленного применения.
